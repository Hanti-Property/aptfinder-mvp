# UI 표시 공통 규칙

모든 화면(관리자·공개·collector 등)에 일관 적용한다.

## 1. 숫자 표시 — 천단위 콤마 (연도 제외)
- **일반 숫자**: 천단위 콤마. 예: `528,772`, `4,424세대`, `239,225㎡`
- **연도**: 콤마 없이. 예: `1979`, `2030` (1,979 아님)
- **코드류**(법정동코드·지번 등): 콤마 없이 원문
- **구현**: `lib/numberFormat.ts`의 `fmtNum(value, key)` / `parseNum(text)` 사용.
  - `fmtNum`: 표시용(콤마). 연도키(YEAR_KEYS/isYearKey)면 콤마 없이.
  - `parseNum`: 저장·계산용(콤마 제거 → number).
  - 편집 셀: focus 시 콤마 제거, blur 시 `fmtNum` 재적용, 저장 시 `parseNum`.
- 새 화면에서 숫자 입력·표시할 때 이 유틸을 쓴다(중복 구현 금지 — 계산 일원화 규칙과 동일 취지).

## 2. 표(테이블) — 모바일 대응
- 셀은 한 줄 고정(`white-space:nowrap`). 넘치면 컨테이너 `overflow-x:auto`로 좌우 스크롤.
- 넓은 표는 좌측 식별 컬럼(#·티커·단지명 등) `position:sticky`로 고정.
- 모바일에서 핵심 컬럼만, 세부는 스크롤로.

## 3. 편집 지점 일원화 (화면 UX)
- 같은 값이 여러 화면/탭에 보이면 **편집은 한 곳(주인)에서만**, 나머지는 읽기전용.
- 데이터는 어차피 DB 컬럼 1개(SoT 유지). 편집 지점만 명확히 해 혼란·중복편집 방지.
- 예: 현재용적률·세대·대지면적 편집은 정비계획 탭, 기본 탭은 읽기전용.

## 4. 가독성
- 셀·입력칸은 터치·시인성 확보(패딩·폰트 충분히). 너무 작은 셀 지양.

## 5. 대시보드 카드 — 새 탭으로 열기
- `/admin` 대시보드의 모든 이동 카드(`<a href="/admin/...">`)는 **새 탭**에서 연다: `target="_blank" rel="noopener"`.
- 이유: 대시보드를 허브로 유지하며 여러 도구를 탭으로 띄워 작업.
- **새 카드 추가 시에도 반드시 `target="_blank" rel="noopener"`** 포함.
